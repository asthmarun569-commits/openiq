# OpenIQ research database data dictionary

## `research_consents`

One record per consent event.

- `id`: random UUID.
- `user_id`: Supabase anonymous-auth user UUID; pseudonymous, not anonymous in the strict legal sense.
- `consent_version`: version of the consent text shown.
- `consented_at`: server timestamp.
- `withdrawn_at`: optional withdrawal timestamp.
- `research_purpose`: fixed purpose string for the current pilot.

Do not store names, emails, phone numbers, exact birth dates, free-text identity fields, or raw IP addresses.

## `assessment_sessions`

One record per completed or attempted session.

- `id`: random UUID.
- `user_id`: owner from Supabase Auth.
- `consent_id`: consent record associated with this session.
- `app_release`: frozen software release identifier, e.g. `0.11.0`.
- `form_id`: fixed form/cohort identifier; do not use a new random value per participant.
- `mode`: `pilot` or `calibration`.
- `age_band`: optional broad band, not exact age.
- `device_class`: optional coarse device class; avoid detailed fingerprinting.
- `started_at`, `completed_at`: timestamps.
- `item_count`: number of presented items.
- `raw_correct_count`: client-reported exploratory raw count; **untrusted and not an IQ score**.
- `client_reported_total`: number of responses reported by the browser.

## `item_responses`

One record per item per session.

- `session_id`, `user_id`: parent session and owner.
- `item_id`: stable item ID generated by the assessment.
- `domain_code`, `template_id`: experimental item classification.
- `item_order`: presentation order.
- `selected_option_label`: selected answer label as displayed; null if unanswered. This is stored instead of an index because the current export provides the answer label, not a trustworthy selected index.
- `is_answered`: whether an option was selected.
- `response_time_ms`: time from options appearing to first selection; null if unanswered.
- `stimulus_duration_ms`: presentation duration when applicable.
- `client_reported_correct`: client-reported correctness for exploratory diagnostics only; not trusted as authoritative.

## Data-quality notes

- Duplicate `item_id` values within a session are prohibited by a unique constraint.
- The app/form version is stored with every session.
- Client-side correctness and raw scores are untrusted because the item bank and answer keys are delivered to the browser.
- Researchers should validate response count against the frozen form manifest before analysis.
- Do not compare raw percentages directly with IQ scores.

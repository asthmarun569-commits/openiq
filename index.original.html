Research & validation

How the OpenIQ prototype is structured—and what would be needed for stronger claims.

01 / Construct

Define what is measured

Each item is tagged to one primary domain. Domain labels are a design framework, not proof that the item measures a validated psychological construct.

02 / Item quality

Review the item bank

Use stable item IDs, answer keys, explanations, version history and documented revisions. Check for ambiguity, cultural bias and accessibility barriers.

03 / Pilot data

Collect consented responses

Recruit an appropriate pilot sample, document inclusion criteria and protect participant privacy. Do not infer population norms from a small convenience sample.

04 / Reliability

Test score consistency

Evaluate internal consistency or suitable reliability measures for the intended score interpretation. A timer alone does not establish processing-speed validity.

05 / Validity

Test the evidence

Gather evidence for content, response processes, internal structure and relationships with relevant external measures. Use qualified psychometric review.

06 / Fairness

Check group differences

Review accessibility, language demands, differential item functioning and subgroup performance before making comparisons.

Current scoring rules

  • Each correctly answered item earns 1 point; incorrect or unanswered items earn 0.
  • Total raw score ranges from 0 to the number of scored items.
  • Domain scores are displayed as raw correct / items in that domain.
  • No IQ conversion, percentile, age norm or diagnostic interpretation is calculated.
  • Time elapsed is recorded only as descriptive session information.

Data and privacy

All data in this version is held in page memory and local browser storage for the question bank. Results are not automatically uploaded. Exported JSON may contain your optional participant code and responses; store it carefully and avoid including personal information.

A static website cannot provide secure multi-user accounts, encrypted central storage, audit trails or server-side access controls. Those require a properly designed backend before a public research study.

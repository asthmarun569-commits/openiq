# OpenIQ v0.11 — Domain and item-review blueprint

## Current intended practice categories (not validated cognitive indexes)

| Internal code | User-facing label | Current task families | Main construct-coverage limitation | Current interpretation allowed |
|---|---|---|---|---|
| VCI | Verbal reasoning practice | Synonyms, instrument analogies, one syllogism | Narrow vocabulary/analogy/logic sample; language and education effects | Raw practice accuracy only |
| WMI | Memory and mental-update practice | Reverse sequences; mental arithmetic update | Only a small number of task families; 3-second presentation is a prototype, not standardized | Raw practice accuracy only |
| PRI | Numerical rule and pattern practice | Arithmetic sequence, doubling rule, side-count arithmetic | Mostly numerical rules; does not establish perceptual or visual-spatial reasoning | Raw practice accuracy only |
| PSI | Visual comparison practice (not standardized speed testing) | Target symbol presence; number comparison | No standardized speed limit; browser, display, device, and input effects are uncontrolled | Raw practice accuracy only; timing exploratory |

## Item review template

For every item version, reviewers should record:

- stable item ID and item version
- intended skill and domain rationale
- exact prompt, stimulus, options, key, and explanation
- whether only one answer is defensibly correct
- language, culture, education, accessibility, motor, device, and strategy demands
- expected difficulty rationale (clearly marked as a hypothesis until empirically estimated)
- cognitive-interview observations and revision history
- pilot difficulty (proportion correct and confidence interval), corrected item-total relationship, missingness, and response-time distribution when sufficient data exist
- reviewer decision: retain, revise, retire, or collect more evidence

## Review rules

1. Do not call a practice category a validated VCI/WMI/PRI/PSI index.
2. Do not treat heuristic difficulty tags as observed item difficulty.
3. Do not compare randomized raw scores as equivalent without calibration/linking evidence.
4. Do not interpret browser response time as a standardized processing-speed score.
5. Do not convert raw scores to IQ until a defensible scoring model, relevant norms, reliability, validity, and independent validation are established.
6. A content reviewer should evaluate the item itself; automated tests can verify keys/options but cannot prove the intended construct is measured.
